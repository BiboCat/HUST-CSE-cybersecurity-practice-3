开头的`jz short near ptr loc_401909+1`和`short near ptr loc_401909+1`反正无论如何都会跳转，关键在于这个`+1`。

**`loc_401909`标签地址在`0x401909`上，`+1`使得程序的实际跳转点是`0x40190A`——但是IDA逆向反编译是静态的，它依然会从`0x401909`开始读指令反编译，而实际上这不是程序的真正功能，所以当然会报错，无法反编译。**

要解决这个问题，最好的方法是动态调试，但是我不会。所以有另一种方法：我们自己从`0x40190A`开始读指令，**自己把二进制反编译一下**！

当然不可能自己做，其他工具又不会用——所以直接从`0x40190A`开始复制二进制机器码，丢给AI帮解析！

复制`74 03 75 01 48 74 03 75 01 FF b8 00 00 00 00 48 8D 0D 20 F8 07 00 0F B6 14 07 83 F2 7C 3A 14 01 75 10 48 83 C0 01 48 83 F8 2A 75 EA B8 01 00 00 00 C3 B8 00 00 00 00 C3`

AI还跑出来一个坑：就是上面不止一处垃圾！

反编译为C如下：

```c
int check_flag(const char *input)          // rdi = input, 返回 eax
{
    const unsigned char *key = /* [rip+0x7F820] */;
    unsigned long i = 0;
    do {
        if ((unsigned char)(input[i] ^ 0x7C) != key[i])
            return 0;
    } while (++i != 42);
    return 1;
}
```

看来是把`flag`和`0x7C`异或后与`key`比较！`key`在`0x481140`，用`rip + 0x7F820`可以算出，这条指令`lea rcx, [rip + 0x7F820]`的`rip`是`0x401914`。

`key`如下：`1A 10 1D 1B 07 1A 4D 1F 4F 19 49 1E 4B 51 4E 18 48 1D 51 48 45 4A 44 51 44 1D 4C 1F 51 4A 19 45 1E 4F 1A 4B 4D 49 18 4E 4C 01`
