### 内网渗透与高级社工-终端EDR绕过-G2

#### 题目

目标主机的终端检测响应（EDR）代理升级为进程行为监控：它追踪运维命令派生出的每一个子进程，一旦服务/脚本进程派生出工具或解释器进程即判定高危并阻断。你需要在不派生受监控子进程的前提下读取 `/flag`。

#### 子进程学习

没事我会问AI：

| 情况                                    | 是否产生新进程                 |
| ------------------------------------- | ----------------------- |
| **内建命令，直接执行**（`cd /tmp`、`export A=1`） | 否，在当前 shell 进程内         |
| **外部命令，直接执行**（`ls`、`grep`、`git`）      | 是，fork + exec           |
| **内建命令，放在 `\|` `$()` `( )` `&` 里**    | **是**，被扔进子 shell        |
| 函数、alias、`if/while` 等关键字              | 否（它们不是进程，是 shell 自己的逻辑） |

- 首先分`内建命令`和`外部命令`，直接执行的情况下，前者不产生子进程，后者产生。

- 然后是关于管道`|`和容器`()`，它们本来的实现方法就是创建一个子进程调用。

- 还有一类关键字不是进程，是判断逻辑。

可以使用`type`命令查看一个命令是内建命令还是外部命令！

#### 重定向

值得注意的是，管道`|`会产生子进程，而重定向`<`、`<<`、`<<<`、`>`、`>>`、`2>>`等不会产生子进程！

然后关注一个命令：`read`。

**`read` 命令用于从标准输入读取一行数据，并将其赋值给一个或多个变量。**

`<`是读取文件内容`stdin`重定向，和可以和`read`搭配使用！

构造如下payload：`a=3;read a < "/flag";echo $a;`即可！

好了已经拿到flag！

#### 补充

关于`read`这个命令，有一个选项`-a`，可以读取输入到数组中；默认分隔是按行分，可以以`IFS="<分隔符>"`作为前缀规定本次read命令的分隔符。这个结构在脚本编写中很常见！

关于重定向符号，我整理复习一下我知道的几个：

| 符号          | 功能                    |
|:-----------:|:---------------------:|
| `< f`       | 从文件读取内容作为stdin        |
| `<< EOF`    | 以EOF为标识，嵌入一段文本作为stdin |
| `<<< "str"` | 把字符串作为stdin           |
| `> f`       | stdout，覆写目标文件         |
| `>> f`      | stdout，追加写入目标文件       |
| `2> f`      | stderr，覆写目标文件         |
| `2>> f`     | stderr，追加写入目标文件       |

#### 总结与防御建议

总的来说，复习和补充了一些关于重定向和子进程的知识。

防御建议：当然不建议把子进程作为过滤标准，不仅防御不了，而且还没有实际意义。
