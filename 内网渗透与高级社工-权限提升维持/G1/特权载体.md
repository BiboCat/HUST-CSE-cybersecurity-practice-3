### 特权载体

特权载体+分外功能=权限漏洞！

#### 特权载体的类型

| 载体               | 特权绑在             | 表现形式          | 怎么枚举                                     |
| ---------------- | ---------------- | ------------- | ---------------------------------------- |
| **SUID / SGID**  | **文件本身**         | `ls -l` 有 `s` | `find / -perm -4000 -type f 2>/dev/null` |
| **sudo**         | **一张配置表**(用户→命令) | `sudo -l` 列出来 | `sudo -l`                                |
| **capabilities** | **文件本身,但被切碎**    | `getcap` 看得出  | `getcap -r / 2>/dev/null`                |

- **`sudo`是免密码即可sudo执行的命令作为特权载体**

使用命令`sudo -l`就可以看见，里面看见的命令就可以添加`sudo`前缀提权执行。

- **`SUID/SGID`是给一类命令配置运行时获取更高权限，被配置的命令即特权载体**

`SUID`配置的命令，执行时会"以所属用户权限"执行。比如给`cat`配置，那么使用该命令时就以它所属的用户权限执行（root），嗯是这样。就可以访问只能root权限访问的文件。

同理`SGID`则是"同组Group"，使用这类命令时，就以它所属的用户组权限执行（root的组），就可以访问允许root组访问的权限。（这个利用比较少，主要是SUID）

**`find / -perm -4000 -type f 2>/dev/null`用于探测有SUID的命令：**
`-perm -4000`的意思是寻找权限为`4000`的。`4000`是Linux权限的表示方式，可以去搜一下，在此不赘述。
`2>/dev/null`是`stderr`重定向，用于排除查找故障，让回显结果更简洁。

`find / -perm -2000 -type f 2>/dev/null`则是SGID的搜索命令。

- **`capabilities`则是文件的一个属性，用于表示该文件/命令拥有什么特权**

`SUID`是给命令发一整个root权限，是一串钥匙；
`capabilities`这个属性中，记载的特权则是root权限的一部分，是钥匙串中的一两把钥匙

使用`getcap /usr/bin/ping`可以看到某个命令的特权属性；
使用`getcap -r / 2>/dev/null`递归扫全盘！

<u>怎么读这些属性呢</u>？
它的输出是形如`cap_net_raw=ep`的字段，前者表示权限类型，后者表示授权情况。

**以下是授权情况表**：

| 字母      | 名字          | 含义                    |
| ------- | ----------- | --------------------- |
| **`p`** | permitted   | **允许**这个进程拥有这项能力      |
| **`e`** | effective   | **生效**——内核做权限检查时看的是这个 |
| `i`     | inheritable | 继承相关,提权场景基本不看         |

**以下是危险的权限类型：**

| cap                       | 一句话              | 危险度                        |
| ------------------------- | ---------------- | -------------------------- |
| **`cap_setuid`**          | 能改自己的 uid        | ⭐⭐⭐ **拿到就通关**              |
| **`cap_setgid`**          | 能改自己的 gid        | ⭐⭐ 通常配合上一条                 |
| **`cap_dac_read_search`** | **无视文件读权限**      | ⭐⭐⭐ 直接读 `/etc/shadow`、flag |
| **`cap_dac_override`**    | **无视读写权限**       | ⭐⭐⭐ 还能**写** `/etc/passwd`  |
| **`cap_chown`**           | 能改任意文件的属主        | ⭐⭐⭐ 把 `/etc/shadow` 改成你的   |
| **`cap_fowner`**          | 无视属主检查           | ⭐⭐⭐ 能 `chmod` 任意文件         |
| **`cap_setfcap`**         | **能给文件设置 cap**   | ⭐⭐⭐ 循环闭合(见下)               |
| **`cap_sys_admin`**       | 相当于半个 root(能挂载等) | ⭐⭐⭐ 威力最大,利用最麻烦             |
| **`cap_sys_ptrace`**      | 能注入其他进程          | ⭐⭐ 可注入 root 进程             |
| **`cap_sys_module`**      | **能加载内核模块**      | ⭐⭐⭐ 等于完全控制内核               |
