## 学习笔记精选

> 这 5 篇是本仓库最有价值的部分：**脱离具体题目**把一类知识重新梳理了一遍，可以直接当速查手册使用。

### 1. [OAuth 2.0 笔记：从零到整条链](内网渗透与高级社工-社交平台钓鱼/G3/OAuth2_笔记_DSH编写.md) · 369 行

从「三个角色最容易乱」讲起，把授权码流程拆成**五棒交接**，每一棒标明谁把什么交给了谁、以及为什么必须这样设计。

- 用生活化的类比锚定四个核心零件：`access_token` = 临时通行证、`code` = 干洗店小票、`client_secret` = 公章、`redirect_uri` = 自己家的门牌。
- 最有价值的一节是**为什么非要两条通道**（前端拿 code、后端换 token），这是理解整条链的设计动机所在。
- 附 PKCE / OIDC / `refresh_token` 等扩展、名词对照表，以及一份「都能答上来就算懂了」的自检清单。

配套还有一份实验台的使用说明：[`oauth-lab/README.md`](内网渗透与高级社工-社交平台钓鱼/G3/oauth-lab/README.md)（242 行），含实测记录与按错误码组织的排错表。

### 2. [CSP 速查](内网渗透与高级社工-社交平台钓鱼/G4/csp-cheatsheet.md) · 165 行

按「读一份策略时该怎么对查」组织，而非按 W3C 规范顺序罗列。

- 两种下发方式（响应头首选 / `<meta>` 次选且功能受限）与**指令对查表**：取源类、导航框架类（**不回退到 `default-src`**，必须单独写）、执行 DOM 类、传输上报类。
- 「收到一份策略时的对查流程」+「最小推荐基线」，实战时可直接照做。

### 3. [特权载体](内网渗透与高级社工-权限提升维持/G1/特权载体.md) · 71 行

核心是一句话公式：**特权载体 + 分外功能 = 权限漏洞**。然后用一张表把三类载体按「特权到底绑在哪」切开：

| 载体 | 特权绑在 | 怎么枚举 |
|---|---|---|
| SUID / SGID | 文件本身 | `find / -perm -4000 -type f 2>/dev/null` |
| sudo | 一张配置表（用户→命令） | `sudo -l` |
| capabilities | 文件本身，但被切碎 | `getcap -r / 2>/dev/null` |

- 对 capabilities 的理解方式：**SUID 是给命令发一串钥匙，capabilities 只是钥匙串里的一两把钥匙** —— 所以要盯的是 `cap_dac_read_search` 这类「一把就能开 flag」的单个能力。
- 附授权位 `p` / `e` / `i` 的含义、9 种危险 capability 按危险度排序的清单，以及 GTFOBins。

### 4. [传说中的过时玩意——JSONP](内网渗透与高级社工-社交平台钓鱼/G4/Jsonp.md) · 36 行

用很短的篇幅讲清了 JSONP 的**来龙去脉**：同源策略下 `<script src>` 是少数能跨域取数据的标签，而它拿到数据后**直接当 JS 执行、不回显到页面**，于是有了「服务端只管把 `{callback}(数据)` 拼成字符串」这个约定，也解释了 callback 参数不可控时为何直接变成注入点。

## 环境与工具链

> 下列版本为脚本与 Writeup 中**实际出现**的版本信息，未标注版本的项以各题正文为准。

| 类别 | 工具 / 依赖 | 版本与说明 |
|---|---|---|
| 语言 | Python 3 | 通用脚本 `python3` 即可；`rc4tool.py` 要求 **3.8+**（使用 `list[str]` 注解与 `\|` 联合类型） |
| Python 库 | 标准库 | 绝大多数脚本仅用 `socket / struct / re / urllib / json / argparse` |
| Python 库 | pwntools | 仅 `安全补丁对比分析/G3/exp/exp.py` 依赖 |
| 反汇编 | **IDA** | `DEP`、`GS`、`软件逆向静态分析`、`安全补丁对比分析` 四个专题的主要工具（字符串视图 `Shift+F12` + 交叉引用 `X`） |
| 反编译 | **Ghidra** | `Ghidra工具使用` 专题主要工具 |
| 十六进制 | **HxD** | `Binwalk工具使用` G3 / G4 的结构定位与手工取数 |
| 固件分析 | **binwalk3** | 版本 **3.10.0**（Kali 仓库）；调用名为 `binwalk3`，常用 `-e` 提取、`-E` 熵图、`-V` 版本 |
| 靶机环境 | Linux 靶场 | 权限提升 / EDR 类题目为 Web 终端，登录用户 `player`，目标 `/flag` |
| 靶机环境 | Win32 / ELF 靶场 | PWN 类题目为「token 靶机（TCP）+ flag 靶机（HTTP）」双机结构 |

**靶机约定**（PWN 类专题通用）：

- token 靶机：TCP，默认端口 `9999`，溢出后由 `get_flag` 桩函数返回**一次性 token**（形如 `<9~12 位数字>.<20+ 位字符串>`，有效期 600 秒）。
- flag 靶机：HTTP `http://<IP>:<PORT>/flag?token=<token>`，返回 `vmc{...}`。
- 脚本内已硬编码示例 IP 作为占位，**复现时请替换为你自己的靶机地址**。
- `DEP` / `GS` 两个专题的脚本支持 `-i` 参数以交互方式输入靶机地址；`安全补丁对比分析` 系列需直接修改脚本头部常量。

> 💡 部分 DEP / GS 题目存在**两台靶机时钟不同步**的情况（例如 token 靶机快 48 秒），脚本内已包含等待逻辑，详见对应 Writeup。
